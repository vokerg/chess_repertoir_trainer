# RB-000 Jira execution setup

Date: 2026-07-26

Branch: `north-star/repertoire-builder-foundation`

## Purpose

Add Jira as the execution and coordination mirror for the Repertoire Builder north-star program without replacing repository planning documents as the detailed product and architecture source.

## Delivered

- Created CRT Epic `CRT-2` for the full program.
- Created one Jira Task for every existing immutable RB task:
  - RB-001 / CRT-3 through RB-016 / CRT-18.
- Preserved repository priority through Jira priority mapping:
  - P0 → Highest;
  - P1 → High;
  - P2 → Medium;
  - P3 → Low.
- Added material `Blocks` relationships across the critical dependency chain.
- Verified the CRT workflow supports `To Do`, `In Progress`, `In Review`, and `Done`.
- Added `JIRA.md` with claiming, transition, branch, PR, blocker, report, and completion rules.
- Updated `README.md`, `AGENTS.md`, `TASKS.md`, and `STATUS.md`.

## Decisions

- Repository documents remain the detailed source for scope, acceptance, architecture, decisions, and historical reports.
- Jira is the operational source for assignee, execution state, active branch, PR visibility, and day-to-day blockers.
- One Jira Task maps to one immutable `RB-###` task.
- Planning-only repository states map to Jira `To Do`; active execution maps to `In Progress`; review maps to `In Review`; accepted completion maps to `Done`.
- Pull requests must be visible through Jira comments even when automatic Development-panel linkage is unavailable.
- New RB tasks must receive Jira issues under `CRT-2` during the same coordination change.

## Residual risks

- Repository and Jira status can drift if future agents lack Jira access or ignore synchronization rules.
- Automatic GitHub-to-Jira Development-panel linkage depends on Atlassian/GitHub integration and naming; Jira comments remain the mandatory fallback.
- The initial dependency links cover the material critical path, while repository task files remain the complete dependency definition.

## Recommendation

Keep the current queue unchanged. Before claiming any task, synchronize its repository task file and mapped Jira issue as defined in `JIRA.md`.
