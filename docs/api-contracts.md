# API contracts

## Ownership

`packages/contracts` is an active root workspace consumed by API and client build graphs. Its verified public exports include position-analysis cache and imported-game analysis responses, imported-game browsing and mutation responses, opening-analysis core/performance/top-games responses, persistent imported-game jobs, board-image endpoints, course read models, serializable training, training statistics and training-marathon responses, scenario-training responses, mobile synchronization, Lab performance-by-rating, top-opponents, monthly-games, training-log and tactical-detection reports, opening-struggles queries/responses, repertoire-target definitions, repertoire-coverage course review responses, Lichess connection and bot-challenge responses, and Lichess puzzle rounds. Add schemas only after checking the real service output and consumers; unverified provisional exports are not acceptable.

For each cross-workspace endpoint DTO, `packages/contracts` owns the Zod request/response wire schema and inferred TypeScript types. The API imports schemas at runtime for validation/serialization. Angular normally imports DTO types only, while mobile imports the runtime schemas needed to validate downloaded bundles and attempt-sync responses. Feature-local input schemas may stay with the API when no other workspace consumes them.

Contracts may contain HTTP params/query/body/response schemas, stable wire literals, pagination/error schemas, descriptions, and inferred types. They must not contain Prisma models, Fastify handlers, services, authorization, chess behavior, Stockfish behavior, Angular or React Native state, RxJS, SQLite repositories, or formatting helpers.

## Policies

- Verify the real route, mapper/service output, consuming client, and tests before defining a schema.
- HTTP dates are ISO strings, never `Date` objects.
- `.nullable()` means JSON includes `null`; `.optional()` means the property may be absent.
- Distinguish wire input from normalized internal output when transforms are used.
- Test the schema against actual mapper/service output and representative invalid values.
- Delete handwritten duplicates only after every consuming workspace compiles against the shared contract.
- Public position-analysis lines require `pvUci`. Historical persisted JSON is normalized at the API mapping boundary so legacy rows cannot weaken the wire contract.
- Position-analysis lookup/store/bulk responses and imported-game analysis read/create/ply-mutation responses are exported from `@chess-trainer/contracts/analysis`. The single-store response preserves its legacy `position` alias, analysis-run dates are serialized ISO strings by the existing service mapper, and Angular consumes the inferred imported-game analysis DTOs while keeping its broader in-memory position-cache model local.
- Imported-game tag-refresh and ply-index workflow responses are exported from `@chess-trainer/contracts/imported-games`. The ply-index route converts internal `Date` values to ISO strings at the HTTP boundary, and the Games Angular model consumes the inferred mutation types rather than maintaining handwritten response DTOs.
- Opening-analysis core, performance, and top-games responses are exported from `@chess-trainer/contracts/imported-games`. The schemas cover concrete applied filters, position WDL, opening-book matches, versioned personal move evidence, performance tags/buckets, and recent-game rows. The API converts normalized `Date` filters back to ISO date-time strings at the HTTP boundary, the personal-evidence policy version is a shared stable literal, and Angular consumes the inferred DTOs instead of maintaining duplicate response interfaces.
- Training statistics responses for aggregate summary, line/chapter/course statistics, and subline status are exported from `@chess-trainer/contracts/training`; Angular consumes the inferred DTOs rather than maintaining duplicate response interfaces.
- Training-marathon next-line responses are exported from `@chess-trainer/contracts/training`. Both the prepared-run and direct-selection API routes validate/serialize the same service-built response with that schema, and Angular consumes the inferred response, scope and mode types instead of duplicating them.
- Scenario-training session, history, attempt-result, and dislike responses are exported from `@chess-trainer/contracts/scenario-training`. Persisted session and attempt dates are serialized as ISO strings by the existing service mapper, `importedGameId` is required-but-nullable because imported-game deletion uses `ON DELETE SET NULL`, and `rawEngineJson` is required JSON that may be `null` after an attempt omits raw engine payload. Angular consumes these inferred response DTOs while keeping request and presentation-only state local.
- Lab performance-by-rating requests/responses, top-opponents and monthly-games responses, training-log responses, and tactical-detection run/list responses are exported from `@chess-trainer/contracts/lab`. Persisted Lab dates are converted to ISO strings at the API boundary, stable training-result and tactical-kind literals are shared by request and response schemas, and Angular consumes inferred response DTOs while keeping presentation-only state local.
- Opening-struggles requests, successful responses, coverage status literals, and the bounded-scope `422` response are exported from `@chess-trainer/contracts/opening-struggles`. Angular keeps only its UI criteria model because full-move depth is converted into wire-level plies.
- Repertoire-coverage course review responses are exported from `@chess-trainer/contracts/repertoire-coverage`. The schema mirrors the calculated course summary, serialized imported-game filters, repertoire conflicts, grouped deviation/gap findings, examples, line anchors, and pagination; Angular consumes the inferred response types rather than maintaining a handwritten DTO.
- Lichess connection status, bot-challenge options/results, and disconnect responses are exported from `@chess-trainer/contracts/lichess`. Their schemas reflect the persisted OAuth connection nullability and the safe challenge projection; token material and upstream raw payloads stay backend-only.
- Lichess puzzle round requests, public round state, move results, stable statuses and feature errors are exported from `@chess-trainer/contracts/lichess-puzzles`. Public puzzle DTOs expose the normalized position, trigger move, orientation, rating, themes and solution length, but never the server-owned solution moves or OAuth token.
- Persistent job kinds, sources, run/task statuses, creation/cancel/retry responses, read summaries, ordered task responses, pagination inputs, and stable errors are exported from `@chess-trainer/contracts/jobs`. A task's `importedGameId` is nullable because persisted task history survives source-game deletion. Task responses include nullable ISO-8601 `startedAt` and `settledAt` fields for the most recent claimed execution attempt; duration is derived from those timestamps and is absent when either is null. Prisma rows and active execution keys remain backend-only. Terminal job dismissal is an ownership-scoped `DELETE` operation; active jobs return `JOB_RUN_NOT_DISMISSIBLE`, while successfully dismissed jobs disappear from all user-facing job reads.

The package exports compiled `dist` files. Focused API and mobile scripts prepare both `chess-domain` and `contracts`; focused web scripts prepare `contracts`. This keeps focused commands valid after `npm ci` without importing unpublished package source.

See [OpenAPI](openapi.md) for route documentation conventions.
